# Техническое задание (ТЗ): Интеграция PWiK Piaseczno iBOK для Home Assistant

## 1. Введение и цель проекта
Разработка пользовательской интеграции Home Assistant (HACS) для личного кабинета клиентов Przedsiębiorstwo Wodociągów i Kanalizacji w Piasecznie Sp. z o.o. (iBOK PWiK Piaseczno, `https://ibok.pwikpiaseczno.pl/`), предназначенной для:
1. Авторизации по учетной записи (логин и пароль) через UI Home Assistant (Config Flow), с возможностью выбора привязанного локального сенсора расхода воды (`source_sensor`) для каждого счетчика (например, импульсный счетчик на ESPHome или Zigbee).
2. Предоставления сервиса `pwik.submit_reading` для автоматической передачи показаний счетчиков воды из сценариев и автоматизаций Home Assistant (например, ежемесячно по расписанию).
3. Создания полного набора диагностических и информационных сенсоров для каждого зарегистрированного водосчетчика (как основного `N`, так и подлинейного/садового `P`):
   - **Последнее подтвержденное показание** (`sensor.<meter_id>_last_reading`): объем в кубических метрах ($m^3$), класс устройства `water`, `state_class: total_increasing`.
   - **Дата последнего показания** (`sensor.<meter_id>_last_reading_date`): дата предыдущей фиксации.
   - **Статус передачи показаний** (`sensor.<meter_id>_reading_submission_status`): текущий статус (`allowed` — доступно к подаче, `pending` — ожидает подтверждения оператором, `in_progress` — в обработке, `rejected` — отклонено, `approved` — утверждено).
   - **Текущее переданное показание** (`sensor.<meter_id>_pending_reading`): значение, находящееся на проверке у оператора.
   - **Расход с прошлого показания** (`sensor.<meter_id>_consumption_since_last_reading`): расход воды с момента последней подтвержденной биллингом подачи ($m^3$), рассчитываемый в реальном времени при наличии связанного локального датчика.
4. Предоставления UI-кнопок:
   - `button.<meter_id>_submit_reading` — подача показания из привязанного локального сенсора в один клик.
   - `button.<meter_id>_cancel_reading` — отмена поданного показания (если оно находится в статусе ожидания `pending`).
5. Корректного брендирования, мультиязычной локализации (PL, EN, RU) и полной совместимости со стандартами современного Home Assistant Core.

## 2. Результаты реверс-инжиниринга веб-интерфейса iBOK PWiK Piaseczno

Веб-система iBOK построена на платформе Spry / MooTools с сессионным REST/AJAX API через PHP backend.

### 2.1. Спецификация авторизации и управления сессиями
- **Базовый URL**: `https://ibok.pwikpiaseczno.pl/`
- **Проблема параллельных сессий**: Портал жестко ограничивает 1 активную сессию на пользователя. При наличии незакрытой сессии сервер возвращает блок `#loginWrongSessionLimit` с сообщением *"Jesteś zalogowany na innym urządzeniu lub innej przeglądarce."*.
- **Сброс зависших сессий**:
  - `GET https://ibok.pwikpiaseczno.pl/?logout=true&kill=true` — принудительно завершает и сбрасывает предыдущие сессии пользователя.
- **Вход в систему (POST)**:
  - **URL**: `POST https://ibok.pwikpiaseczno.pl/?`
  - **Заголовки**:
    - `Content-Type: application/x-www-form-urlencoded`
    - `User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 ...`
  - **Тело формы**:
    ```
    JSTest=ok&user=<username>&pass=<password>&login=Zaloguj
    ```
  - **Алгоритм надежной аутентификации**:
    1. Выполняется предварительный `GET /?logout=true&kill=true` для очистки чужих сессий.
    2. Выполняется `POST /?` с учетными данными.
    3. Если в ответе обнаружен маркер `#loginWrongSessionLimit`, выполняется повторный вызов `GET /?logout=true&kill=true` и повторный `POST /?`.
    4. Успех определяется по наличию сессионной cookie `PHPSESSID` и отсутствию ошибок авторизации на странице.

### 2.2. Спецификация эндпоинтов получения данных

1. **Список счетчиков и текущие статусы показаний**:
   - `GET https://ibok.pwikpiaseczno.pl/?module=NotifyReadout_v1`
   - **Формат ответа**: JSON-массив объектов водосчетчиков:
     ```json
     [
       {
         "numer_fabryczny": "72130027",
         "id_wodom": "87994",
         "zakres": "100000",
         "min_zakres": "0.001",
         "l_cyfr_l": "5",
         "jednostka": "",
         "fl_podl": "N",
         "adres": "Lidii Wysockiej 35 , 05-500 Julianów",
         "nazwa": "",
         "leg_do": "2028-12-31",
         "leg_do_wyg": 0,
         "io": "2455037",
         "do": "2026-09-16",
         "sl": "269.000000",
         "prz": 1,
         "id": "51632",
         "iio": "2397608",
         "ido": "2026-08-03",
         "isl": "254.130000",
         "wzuz": 100229.13,
         "zuz": 99985.13,
         "iid": "87994",
         "inr": "72130027",
         "ist": "4",
         "kkom": "",
         "tkom": "brak komentarza",
         "zal": "0",
         "zaln": null
       }
     ]
     ```
   - **Описание ключевых полей**:
     - `numer_fabryczny`: серийный номер счетчика (Meter ID).
     - `id_wodom`: внутренний идентификатор счетчика в биллинге PWiK.
     - `fl_podl`: тип подключения (`N` — Główny / основной счетчик, `P` — Podlicznik / садовый/дополнительный).
     - `do`: дата предыдущего расчетного показания (`YYYY-MM-DD`).
     - `sl`: значение предыдущего расчетного показания ($m^3$).
     - `io`: внутренний ID предыдущего показания (передается в поле `odcz_poprz` при подаче).
     - `ist`: статус текущей заявки на подачу показания:
       - `1`: Oczekujące (`pending`) — ожидает обработки оператором (доступно для отмены).
       - `2`: W trakcie realizacji (`in_progress`) — в процессе утверждения.
       - `3`: Odrzucony (`rejected`) — отклонено оператором.
       - `4`: Zatwierdzony / Poprzedni (`approved` / `allowed`) — показание утверждено, доступна новая подача.
     - `ido`: дата последней поданной заявки.
     - `isl`: значение последней поданной заявки.
     - `min_zakres`: точность дробной части счетчика (например, `"0.001"` — 3 знака, `"0.1"` — 1 знак).
     - `zakres`: предельная разрядность целой части.

2. **История показаний счетчиков**:
   - `GET https://ibok.pwikpiaseczno.pl/?module=Readouts_v1`
   - Возвращает массив точек учета с историческими данными (`odczyty`: дата `do`, показание `sl`, расход `zu`, тип `typ`).

3. **Журнал системных ошибок и сообщений**:
   - `GET https://ibok.pwikpiaseczno.pl/?module=Errors`
   - Возвращает JSON-массив сообщений:
     ```json
     [
       {
         "errorText_": "<base64_encoded_text>",
         "errorType_": "<base64_encoded_type>"
       }
     ]
     ```
   - Значения `errorType_`: `SCC` (успех), `ERR` (ошибка), `WRN` (предупреждение). Все тексты раскодируются из Base64.

### 2.3. Спецификация передачи и отмены показаний

1. **Подача нового показания**:
   - **URL**: `POST https://ibok.pwikpiaseczno.pl/?module=NotifyReadout_v1&action=add`
   - **Формат**: `multipart/form-data`
   - **Поля формы**:
     - `id_wodom`: строковый идентификатор счетчика (`id_wodom`).
     - `odcz_poprz`: ID предыдущего показания (`io` из датасета `NotifyReadout_v1`).
     - `txtDateOfReading`: дата показания в формате `YYYY-MM-DD` (по умолчанию текущая дата).
     - `txtReadingNr`: целая часть показания (строка из цифр, например `"270"`).
     - `txtReadingFrac`: дробная часть показания (строка из цифр, например `"000"`, с длиной не более разрядности `min_zakres`).
     - `txtDesc`: текстовый комментарий клиента (опционально, например `"Podano przez Home Assistant"`).
     - `txtAttachment`: файл вложения (пустое вложение `filename=""`, `Content-Type: application/octet-stream`).
   - **Контроль результата**:
     - Сразу после POST-запроса проверяется эндпоинт `GET /?module=Errors`.
     - При наличии сообщений типа `ERR` генерируется исключение `HomeAssistantError` с расшифрованным текстом ошибки.
     - При отсутствии ошибок или наличии `SCC` данные немедленно обновляются вызовом `NotifyReadout_v1`.

2. **Отмена ранее поданного показания**:
   - **URL**: `POST https://ibok.pwikpiaseczno.pl/?module=NotifyReadout_v1&action=remove`
   - **Формат**: `application/x-www-form-urlencoded`
   - **Поля**: `txtIdOdczytu=<id>` (поле `id` заявки со статусом `ist == 1`).

## 3. Архитектура интеграции для Home Assistant

### 3.1. Структура файлов компонента
```
custom_components/pwik/
├── brand/
│   ├── icon.png
│   └── logo.png
├── __init__.py            # Инициализация платформ, регистрация сервисов
├── manifest.json          # Метаданные интеграции
├── const.py               # Константы, домен, эндпоинты
├── config_flow.py         # Настройка через UI (логин, пароль, выбор source_sensor)
├── coordinator.py         # DataUpdateCoordinator (периодический опрос, кэш, синхронизация)
├── api.py                 # Асинхронный клиент на aiohttp (чистый Python, без внешних библиотек)
├── sensor.py              # Реализация сенсоров счетчиков воды
├── button.py              # Кнопки подачи показания и отмены
├── services.yaml          # Описание параметров служб submit_reading и cancel_reading
├── strings.json           # Строки локализации
└── translations/
    ├── en.json
    ├── pl.json
    └── ru.json
```

### 3.2. Требования к отказоустойчивости и безопасности
1. **Асинхронность**: все сетевые операции должны выполняться исключительно через `aiohttp` с использованием `async_get_clientsession(hass)` без блокировки Event Loop.
2. **Обработка сессий**: автоматическое обнаружение `loginWrongSessionLimit` и разрыв зависших сессий через `?logout=true&kill=true`.
3. **Строгая валидация входных данных**:
   - Разделение числа с плавающей точкой на целочисленную часть (`txtReadingNr`) и дробную часть (`txtReadingFrac`).
   - Проверка монотонного возрастания показания ($reading \ge last\_reading$).
   - Проверка даты (дата не может быть в будущем и не может быть раньше предыдущего показания).
   - Защита от спама и повторных отправок: если заявка уже находится в статусе ожидания (`ist == 1`), вызов блокируется.
